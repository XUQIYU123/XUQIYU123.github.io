STM32 ADC 实战笔记：从光敏控灯到定时采样波形

前言

这次完成了两组 ADC 实验：一组用光敏传感器采集模拟量控制 LED 亮灭，另一组用定时器定时触发 ADC，把电压值通过串口送到电脑画出波形。顺带把 FreeRTOS 多任务的概念先摸了一遍。

真正卡人的不是”调一个库函数读寄存器”这件事，而是采样时间到底该配多少——它由前端电路的内阻决定，配短了数据全是噪声。所以这篇笔记花了不少篇幅在电路等效和周期换算上。

本文的知识路线：

    flowchart TD
    A["ADC 内部结构<br/>多路选择 / 采样保持 / SAR / 结果寄存器"] --> B["前端电路<br/>光敏分压 + 戴维南等效"]
    B --> C["采样时间计算<br/>Ts = (R_AIN + R_ADC) x C_ADC"]
    C --> D["周期档位选型<br/>3.4 周期 -> 取 7.5 周期"]
    D --> E["实验一：软件触发<br/>光敏 ADC 控制 LED"]
    D --> F["实验二：定时器 TRGO 触发<br/>1ms 采样 + 串口上传"]
    F --> G["VOFA+ 波形显示"]
    E --> H["小结：采样宁长勿短 / 软硬触发取舍"]
    G --> H

一、先看清楚 ADC 内部在做什么

STM32 内置的是 12 位逐次逼近型（SAR）ADC。它不是一个”读一下就出数”的黑盒，内部有明确的链路：模拟信号先进多路选择器，选定通道后进入采样保持电路给采样电容充电，再由 SAR 内核逐位逼近出 12 位结果，最后落到结果寄存器并置位标志。

    flowchart TD
    IN["模拟输入<br/>AIN0 ~ AIN16"] --> MUX["多路选择器"]
    MUX --> SEQ["序列控制器<br/>常规 / 注入"]
    SEQ --> SH["采样保持电路<br/>采样电容 C_ADC"]
    SH --> SAR["12 位 SAR 内核<br/>逐次逼近"]
    SAR --> DR["结果寄存器<br/>常规 1 个 DR"]
    SAR --> JDR["注入结果寄存器<br/>JDR1 ~ JDR4"]

    TRIG["触发源"] --> SEQ
    TRIG --> T1["软件触发"]
    TRIG --> T2["定时器 TRGO"]
    TRIG --> T3["外部引脚 EXTI"]

    DR --> FLAG["标志位<br/>EOC / JEOC / AWD"]
    FLAG --> INT["ADC 全局中断"]
    DR --> DMA["DMA 请求"]

1.1 两类转换序列

类型 通道数 结果寄存器 特点
常规序列 Regular 最多 16 个 只有 1 个 DR 按顺序批量转换，结果依次写入同一个 DR，适合连续采集
注入序列 Injected 最多 4 个 JDR1 ~ JDR4，共 4 个 优先级高于常规序列，相当于”插队采集”，可保留多组结果不被覆盖

结果寄存器一共 5 个：常规序列 1 个 DR，注入序列 4 个 JDR。这也是为什么多通道常规采集时必须配合 DMA 或及时读走数据——不然上一路的结果会被下一路覆盖。

1.2 三类触发方式

  • 软件触发：代码里调一次启动函数就转一次，适合轮询式简单采集。
  • 定时器外部触发：定时器把更新事件/比较事件输出成 TRGO 脉冲，硬件直接启动 ADC，周期精准且不占 CPU。
  • 外部引脚触发：走 EXTI，适合外部事件来了一起采。

1.3 常用状态标志位

标志位 全称 含义
AWD Analog WatchDog 模拟看门狗，电压越过设定阈值时置位
EOC End Of Conversion 常规序列转换结束
JEOC Injected End Of Conversion 注入序列转换结束

三个标志都能单独开中断。实际开发里最常盯的是 EOC——它就是”这一组转换做完了、可以去读 DR 了”的信号。

二、光敏电路与戴维南等效

实验用的是光敏电阻分压。模块一般把分压节点引到 AO（模拟输出）脚，另一路经比较器给出 DO 数字输出；本实验只用 AO 这一路接 ADC。

2.1 分压电路

固定电阻与光敏电阻串联在 VCC 与 GND 之间，取中间节点电压送 ADC：

    flowchart TD
    VCC["VCC 3.3V"] --- R1["R1 固定电阻 10kΩ"]
    R1 --- NODE(("分压节点<br/>AO -> ADC AIN1"))
    NODE --- R2["R2 光敏电阻<br/>光照越强阻值越小"]
    R2 --- GND["GND"]

光照变强时 R2 变小，节点电压下降；光照变弱时 R2 变大，节点电压升高。所以 ADC 读到的是一个”反向”的光强指标，阈值判断时要按这个方向写逻辑。

2.2 为什么要算信号源内阻

ADC 的采样过程本质上是给内部采样电容充电。信号源内阻越大，充电越慢；采样时间给不够，电容还没充到目标电压就被拿去转换，结果必然偏低且随环境抖动。

所以必须先求出这个分压电路的等效内阻——这就是戴维南定理要解决的问题。

2.3 戴维南定理到底在说什么

定理的原始表述：任何一个线性有源二端网络，对外接负载而言，都可以等效成一个理想电压源串联一个电阻。

  • 等效电压源的电压 = 该网络端口的开路电压 Uth
  • 串联电阻的阻值 = 网络内部独立源全部置零后的端口等效电阻 Req

三个关键词得先拆清楚：

关键词 含义 在我们这里是什么
二端网络 只有两个对外接线端子的电路 AO 与 GND 两个端子
线性 只由电阻、电压源等线性元件组成 R1、R2 都是线性电阻，符合
独立源置零 电压源短路（理想电压源内阻为 0，短路后两端电压为 0）、电流源开路 只有 VCC 一个电压源，直接短接到地

置零这一步的物理含义是：求等效电阻时要让电路”没有能量输入”，只看它本身对电流的阻碍有多大。

2.4 标准两步法

所有线性二端网络求戴维南等效，走的都是同一个流程：

    flowchart TD
    A["线性有源二端网络<br/>光敏分压电路"] --> B["步骤 1：断开外接负载<br/>求端口开路电压 Uth"]
    A --> C["步骤 2：独立源置零<br/>VCC 短接到地"]
    B --> D["等效电压源 Uth"]
    C --> E["从端口向内看的等效电阻 Req"]
    D --> F(("戴维南等效电路<br/>Uth 串联 Req"))
    E --> F
    F --> G["接 ADC 采样端 AIN1"]
  • 求开路电压：把负载（这里是 ADC 输入引脚）断开，此时端口没有电流流出，量到的电压就是信号能输出的最高理论电压。
  • 求等效内阻：把 VCC 短路后，从两个端口往里看的总电阻。它决定了信号的驱动能力——内阻越大，带负载能力越弱，给采样电容充电越慢。

2.5 套到光敏分压电路上

光敏电阻转戴维南等效电路图:

第一步，求开路电压。 断开 ADC 后，R1 与 R2 就是纯串联，按串联分压：

第二步，求等效内阻。 把 VCC 短路到地，从 AO 与 GND 两个端子向内看：

  • R1 的上端原本接 VCC，VCC 短路后等于接在 GND 上
  • R2 的下端本来就接 GND
  • 于是 R1 与 R2 变成一端都接 AO、另一端都接 GND的并联结构

所以：

    flowchart LR
    VTH["等效开路电压<br/>Uth = VCC x R2 / (R1 + R2)"] --> SRC(("戴维南等效信号源"))
    REQ["等效内阻<br/>Req = R1 // R2 = R1 x R2 / (R1 + R2)"] --> SRC
    SRC --> ADC["接 ADC 采样端<br/>AIN1"]
    GND["GND"] --- SRC

到这里，”一个分压电路”就被压缩成了”一个电压源串一个电阻”。往后算采样时间，只需要面对这两个量，不必再回头分析整块电路。

2.6 为什么工程上直接取 10kΩ

并联电阻有个铁律：两个电阻并联，总阻值一定小于其中任意一个。

结合光敏电阻的阻值范围：

光照条件 R2 阻值 等效内阻 Req 结论
强光 几百 Ω 量级 远小于 10kΩ 充电快，好采
中等 与 10kΩ 相当 约 5kΩ 一般
弱光（暗） 几 MΩ 量级 近似等于 R1 ≈ 10kΩ 内阻最大，最难采

也就是说整个电路的最大等效内阻不会超过 10kΩ。工程上为了保证最恶劣工况（内阻最大、充电最慢）下采样仍然准，直接按 10kΩ 这个上界算采样时间——只要最坏情况够用，其他情况自然够用。这就是”保守取值”的全部理由。

2.7 内阻怎么落到采样时间上

内阻确定之后，充电过程就是一阶 RC 电路，时间常数：

其中 R_ADC 是 ADC 内部采样开关的导通电阻（约 1kΩ），C_ADC 是采样电容（约 77.6pF）。τ 越大，电容逼近目标电压越慢。

注意：τ 只是”充到 63%”的时间，不是”充够精度”的时间。按 12 位精度要求充到 1/2 LSB 以内，需要的时间约为 ln(2^13) ≈ 9 个 τ 量级，比 0.85μs 大得多。所以下面的计算只是起点估算，最终档位要靠实测噪声反过来验证——这也是为什么本实验选 7.5 周期就能用，但真要高精度还得往 28.5、41.5 这些大档位加。

下一节就按这个思路，从 10kΩ 出发把采样时间和周期档位算一遍。

三、采样时间怎么算、周期怎么选

3.1 采样时间估算

按一阶 RC 充电估算时间常数（采样电容 C_ADC ≈ 77.6pF，内部采样开关串联电阻 R_ADC ≈ 1kΩ）：

说明：这里按时间常数 τ 估算，只是起点。2.7 已说明，按 12 位精度真正充到 1/2 LSB 需要多个 τ，所以最终档位要靠实测噪声反向验证，别把 0.85μs 当成”够用时间”。

3.2 换成”周期数”才能配寄存器

ADC 时钟配的是 4MHz，一个 ADC 时钟周期 = 0.25μs。把时间换成周期数：

但 STM32 的采样周期只能从固定档位里挑：1.5 / 7.5 / 13.5 / 28.5 / 41.5 / 55.5 / 71.5 / 239.5。

没有 3.4 这一档，只能向上取 7.5 周期。这里必须是”向上”，往下取就等于主动牺牲精度。

3.3 一次完整转换要多久

12 位 SAR 的固定转换时间是 12.5 个周期，采样与转换串行：

    flowchart LR
    T0["触发到来<br/>t = 0"] --> TS["采样阶段<br/>7.5 周期<br/>= 1.875 μs"]
    TS --> TC["逐次逼近转换<br/>12.5 周期<br/>= 3.125 μs"]
    TC --> EOC["EOC 置位<br/>总计 20 周期 = 5 μs"]

也就是说最快 5μs 出一次 12 位结果，理论上限约 200kSPS。这个 5μs 后面还会用到——它是判断”1ms 触发一次会不会丢触发”的依据。

四、实验一：软件触发 ADC 控制 LED

4.1 目标

ADC 采光敏分压电压 → 换算成电压值 → 与阈值比较 → 控制 LED。

4.2 配置

项目 取值
通道 AIN1
触发方式 软件触发
序列 常规序列
采样周期 7.5 周期
数据对齐 右对齐
结果位宽 12 位（0 ~ 4095）
LED GPIOA PIN13 推挽输出

配置顺序：先定采样周期，再选通道（AIN1~AIN16 里挑），最后把外部触发方式设成软件触发。

4.3 三个接口就够了

  • HAL_ADC_Start()：启动常规序列。放 while 外面是”开一次 ADC”，放 while 里面就是”每次循环软件触发一次”——这个区别就是软件触发的全部秘密。
  • HAL_ADC_PollForConversion()：阻塞等 EOC 置位。
  • HAL_ADC_GetValue()：读 DR，拿 12 位原始值。

4.4 程序流程

    flowchart TD
    A["初始化：HAL / 时钟 / GPIO / ADC"] --> B["HAL_ADC_Start 启动转换"]
    B --> C["PollForConversion 等待 EOC"]
    C --> D["GetValue 读 DR 得原始值"]
    D --> E["换算电压<br/>V = raw × 3.3 / 4095"]
    E --> F{"V 是否高于阈值?"}
    F -->|"是，光弱"| G["点亮 LED"]
    F -->|"否，光强"| H["熄灭 LED"]
    G --> B
    H --> B

五、实验二：定时器触发 ADC + 串口上传

5.1 目标

每 1ms 自动采一次，转成电压后经串口发给电脑，用 VOFA+ 画实时波形。

关键点：触发不能靠 CPU 去调函数，否则周期会被其他代码拖歪。改成定时器硬件触发后，采样节拍由定时器决定，和主循环忙不忙无关。

5.2 定时器怎么产生触发脉冲

定时器工作在主模式，把内部事件映射到 TRGO 输出。这里选更新事件（Update）：每次计数器溢出重装时，TRGO 输出一个脉冲，直接送进 ADC 的外部触发端。

    flowchart LR
    CK["定时器时钟 8MHz"] --> PSC["PSC = 7<br/>计数时钟 1MHz"]
    PSC --> CNT["CNT 0 -> 999<br/>共 1000 个计数"]
    CNT --> UEV["更新事件 UEV<br/>每 1ms 一次"]
    UEV --> TRGO["TRGO 输出脉冲<br/>主模式"]
    TRGO --> ADC["ADC 外部触发端<br/>自动启动转换"]
    ADC --> EOC["EOC 置位"]

5.3 触发到出数的完整时序

    sequenceDiagram
    participant TIM as 定时器 TIM
    participant ADC as ADC1
    participant CPU as 主循环
    participant PC as VOFA+

    TIM->>ADC: 每 1ms 输出一次 TRGO 脉冲
    ADC->>ADC: 采样 7.5 周期 + 转换 12.5 周期 = 5μs
    ADC->>CPU: EOC 置位
    CPU->>ADC: HAL_ADC_GetValue 读 DR
    CPU->>CPU: 换算电压 + sprintf 组包
    CPU->>PC: UART 发送 "x.xxx\n"
    Note over TIM,ADC: 距下次触发还有约 995μs，余量充足

一次转换只要 5μs，而触发间隔是 1000μs，余量接近 200 倍，所以不会出现”上一次还没读完、下一次触发又来了”的丢数据问题。

5.4 代码

5.5 上位机显示

VOFA+ 用 FireWater 协议解析：一行一个浮点数，以换行分隔。sprintf(buf, "%.3f\n", v) 正好符合这个格式，接上串口、选对波特率就能直接出波形。

对着波形看能发现两件事：遮住光敏电阻波形会整体抬升或下压，说明分压方向判断对了；波形上的毛刺对应采样档位和电源噪声，如果毛刺过大就说明采样时间还得再加。

六、踩坑记录

  1. 采样周期只能向上取。算出来 3.4 周期，配 1.5 或 7.5 都行，但绝不能往小取——采样电容没充满就转换，读出来的值偏低且随环境漂。宁可慢一点也要准。
  2. 软件触发和外部触发的区别不在”能不能转”，而在”谁决定节拍”。软件触发受主循环影响，周期不稳；定时器触发的周期由硬件保证。
  3. DR 只有一个，别指望它记住历史。常规序列多通道采集必须配 DMA 或每路读完立刻取走，否则数据相互覆盖。
  4. VOFA 格式很挑。只发数字和换行，中间别夹文字、逗号、单位，否则解析失败、界面空着。
  5. HAL_ADC_Start() 的位置就是触发语义。写在 while 外 = 只启动一次；写在 while 内 = 每轮触发一次。这点搞混了会以为是 ADC 不工作。
